    About this format
    
Each byte is coded in the longest context (up to the chosen order) where it has been seen; otherwise an ESCAPE is sent and the coder drops to a shorter context, down to an order -1 table holding every byte value. Order -2 carries the special FLUSH and DONE symbols. Symbols already ruled out in a higher order are excluded from lower-order totals, and only contexts that were used get their counts updated.

    
Every 256 symbols the compressor checks the ratio for the recent stretch; if output exceeds 90% of input it sends FLUSH, which halves every count in the model on both sides.

    
The stream has no header, so the order is not stored in the file: you have to expand with the same order you compressed with. A wrong order usually fails with a sync error, but it can also produce garbage. Files are interchangeable with the DOS/Unix comp-2/expand-2 builds.
